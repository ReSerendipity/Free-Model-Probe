01结论

密钥有效、网络通畅，免费模型整体可用。14/21 个模型一次直连成功并返回真实内容， 本次测试全部请求 cost = 0。7 个失败模型中没有一例是密钥或网络问题：3 个是上游免费共享池临时限流（429， 属于容量问题、间歇可用），2 个是 Google Lyria 对当前地区封锁（403），2 个是 Thinking Machines inkling 官方限定只能在 agentic harness（编码 Agent、生产力应用）内调用（403）。

429 · 上游共享池限流（3 个）

错误元数据 limit_source=upstream_provider_shared_pool，来自 Google AI Studio / Poolside 的免费共享池，与本密钥无关。等待 60–80 秒后复测仍未恢复，属持续高峰。

403 · 地区封锁（2 个）
Google Lyria 音乐模型

路由在「Gate Endpoints with Geo Restrictions」一步被拒，当前网络区域无法调用。二者为 text+audio 音乐生成模型，即使可达也不适合文本任务。

google/lyria-3-clip-preview
google/lyria-3-pro-preview
对策：无（地区硬门槛）；文本场景直接忽略。
403 · 仅限 Agentic Harness（2 个）
Thinking Machines inkling

官方在「Gate Free Endpoints by Agentic Harness」一步拦截：只允许通过编码 Agent、生产力应用等 agentic harness 调用，纯 API 直接请求不开放。

thinkingmachines/inkling:free
thinkingmachines/inkling-small:free
对策：把模型接入 OpenRouter 应用列表中的编码 Agent（如 Cline、Roo Code 等）即可使用。
04值得注意的发现
  1. nemotron-3-ultra 自称 GLM
    nvidia/nemotron-3-ultra-550b-a55b:free 对身份提问的回答是「我是 GLM，Z.ai 训练的大语言模型」，而路由字段仍显示 Nvidia 端点。模型身份与标称不一致，对模型来源敏感的场景需自行验证。
  2. openrouter/free 路由器不保证路由到聊天模型
    本次请求被路由到 nemotron-3.5-content-safety，回答为「User Safety: safe」。该路由器按空闲度在免费模型间随机挑选，要稳定的对话质量应直接指定具体模型 ID。
  3. lightning 的思考链会占用输出预算
    nemotron-3.5-lightning:free 把推理过程直接写进 content（"Here's a thinking process: …"），400 个 max_tokens 全部耗尽、finish=length。作为 Agent 后端时需给足 max_tokens 或改用其他模型。
  4. content-safety 是分类器不是聊天模型
    它在免费清单里且连通，但用途是输入安全审核；做通用对话应排除。
  5. 垂域变体可直接当通用模型用
    ling-3.0-flash-fin（金融）/ -sante（健康）对通用问候回复正常，没有强系统提示词偏移；dots-3-note-preview 也表现正常。

06测试方法

模型清单取自 GET /api/v1/models（430 个），过滤条件与网页一致：ID 以 :free 结尾 或 prompt/completion 计价均为 0，且 output_modalities 含 text → 21 个。每个模型发送单条中文用户消息 （「你好，请用一句话简短介绍你自己。」），max_tokens=400，超时 75s，3 并发；失败自动重试 1 次； 429 模型等待 60s 后再整轮复测一次。判定「可用」= HTTP 200 且返回非空文本。全部原始响应与逐模型结果见 工具集/data/（connectivity_test.json + raw/）。
